# A process and context contract

Semantic reproducibility means preserving intended relationships under stated language and context conditions. It does not require identical wording, and model agreement alone is not correctness.

A usable handoff binds six things:

| Item | Purpose |
|---|---|
| Language/example version | Defines the available operators, vectors and composition rules. |
| State and Trajectory | Separates a disposition from its intended transition. |
| Referents | Identifies the objects, goals and records to which the expression applies. |
| Current revision | Distinguishes current authority from superseded history and foreign goals. |
| Teaching and context | Records which primer, examples, glosses and task facts the interpreter actually received. |
| Observable consequence | Makes interpretation assessable through a proposed or executed next action. |

These bindings belong to the communication system; they need not all be repeated in each message. An established language definition and a shared, current artifact can supply them through the working context. The exchanged chain can direct attention to a process relation in that common object. See [shared-context communication](shared-context-communication.md).

The symbolic carrier addresses a process relation. Exact identifiers, source facts and permissions remain explicit. A compact expression is not a claim that an agent can recover unseen source bytes or facts.

For dRy, State and Trajectory use the same chain syntax but different contextual registers. crY addresses mathematical operations under its own definitions. An operation's spelling is not a shared dRy/crY semantic mapping. Numerical claims additionally need typed operands, domains and an executed reference calculation.

## Three separately assessed properties

1. **Form:** Does an expression conform to the chosen grammar/profile?
2. **Interpretation:** Does its unfolding preserve the independently specified relation, including direction and negation?
3. **Application:** Does the next proposed or executed action respect that relation and the task constraints?

A parser addresses the first question. Similar prose does not settle the second. A proposal is not an executed action for the third.

The [public handoff fragment](../examples/public-fragment/README.md) exposes all definitions required for its limited example. Its evaluator materials are kept separate from sender/recipient inputs. The [evaluation protocol](../research/semantic-reproducibility.md) extends this distinction to repeated and cross-model studies.
